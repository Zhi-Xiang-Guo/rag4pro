# rag4pro 工作台

从项目根目录运行 `docker compose up -d --build --wait` 后，打开 `http://localhost:18080`。API 令牌在工作台页面右上角录入，浏览器按标签页会话保存。模型网关的密钥由服务端读取 `.env`。

## 文档发布与引用

1. 在「知识库」中创建知识库，选择分块方式，再上传 TXT、Markdown、文本 PDF 或 DOCX。文本 PDF 可以直接定位页码，扫描件需要先做 OCR。
2. 等待入库状态变为「可检索」。文档页可以读取分块及其父段或章节窗口，也可以按该文档范围打开问答和检索实验。入库失败时，作业保存错误和重试入口。若期间发布过更新版本，重新打开文档再操作。
3. 「重建索引」可用当前原件调整分块设置，也可上传替换文件。成功之后，新问题使用当前发布版本。旧回答中的引用携带原件版本，通过引用可以继续打开当时的 PDF 页或 Word 正文位置。历史导入的纯文本块可能只有证据正文。
4. 对话可停止等待当前流式回答。完整回答与引用保存在当前浏览器，后续追问使用已经完成的对话轮次。

## 复跑一次检索对照

1. 打开「检索实验」，选知识库与可选文档，输入同一个问题。两组共用 Top K、候选池和证据 token 预算。默认上下文都为「命中块」，可先对照原版混合与 RRF。第二次可以固定召回方式，只改一组的上下文为父段或章节，检查有多少额外证据在预算内出现。
2. 看「命中与证据差异」里的共同块和独有块，展开名次表确认新增块排在什么位置。证据按实际回填后的块 ID 比较。父段或章节进入证据后，其 ID 会与底层命中块不同。共同块和名次变化描述两个结果之间的差异，相关性指标需要题目和人工标注的标准证据。
3. 展开每组的「查看检索阶段」，检查是否发生回退、各路返回候选数和过滤后的数量。原版混合的加权分和 RRF 名次分采用各自尺度。召回耗时包括检索段的查询向量和可选精排调用。完整等待还包括上下文组装与传输。
4. 用「导出配置」保存问题、范围和两组设置，支持下一次「导入配置」。复跑需要相同知识库与文档 ID、索引版本和模型配置。两组都成功后，可单独「导出结果」，包括预算、耗时、阶段计数、命中名次和证据版本。结果文件省略问题与原文内容，范围和分块 ID 仍会写入。

批量数据集上的召回与问答评测见 [评测脚本](../evaluation/README.md)。页面的检索对照可以用来查一条失败样本，核对证据在哪一环丢失。
