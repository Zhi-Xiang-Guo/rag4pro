# rag4pro 分块与检索评测

词法召回沿用 RAGFlow 的多字段评分，正文分词字段使用 Elasticsearch 的默认 BM25，标题等字段使用脚本分数或精确匹配。向量召回单独执行，在 RRF 配置中按两路排名融合。

## HotpotQA 支持句覆盖

从官方 distractor 验证集的 7,405 题按固定哈希排序划出 24 道校准题和 100 道留出题。留出题共 981 篇去重候选文章、239 条标注支持句。每题只搜索数据集为该题提供的候选文章。每条支持句须完整出现在同一篇文章的一个预算内证据块中，才记作命中。[HotpotQA 数据和论文](https://hotpotqa.github.io/)

五组共用 OPay 网关的 `qwen3-embedding-4b`、Elasticsearch 8.11.3、64-token 分块上限、32 个召回候选、最终 Top 8 和 512 个 Cl100k 证据正文 tokens 的上限。固定窗口使用零重叠。每题先预热查询向量，再轮换配置执行顺序。支持文档和支持句召回率按题取平均，完整覆盖按题计数。API p95 来自 `requestMs`，包括召回、回填和响应等开销。

| 配置 | Top 8 块中的支持文档覆盖 | 支持句召回率 | 完整覆盖 | 平均证据 tokens | API p95 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 固定窗口 · RRF · 命中块 | 86.5% | 66.67% | 44/100 | 426.9 | 36.4 ms |
| 多层索引 · RRF · 命中块 | 86.5% | 75.83% | 56/100 | 367.5 | 38.1 ms |
| 多层索引 · RRF · 父段回填 | 86.5% | 79.33% | 64/100 | 481.7 | 50.3 ms |
| 多层索引 · RRF · 章节回填 | 86.5% | 79.00% | 64/100 | 481.5 | 53.7 ms |
| 多层索引 · 文档多样性 RRF · 章节回填 | 92.0% | 80.58% | 66/100 | 486.7 | 54.7 ms |

- **切分。** 保持 RRF 和命中块返回，改用多层索引中的结构子块后，完整支持句覆盖增加 12 题，平均证据用量少 59.4 tokens。
- **回填。** 保持多层索引和 RRF，补入父段将完整覆盖从 56 题提高到 64 题，平均证据用量增加 114.2 tokens。父段组对比固定窗口有 27 题从缺失变为覆盖完整，7 题从完整变为缺失。
- **逐级回退。** 保持检索和向量索引，修复后的父段组和章节组各增加 4 题完整覆盖。章节放不进剩余预算时尝试其父段，父段放不下时继续尝试原始命中块。
- **文档多样性。** 在相同章节回填下，优先纳入不同文章的首个命中后，支持文档召回从 86.5% 到 92.0%，完整覆盖从 64 题到 66 题。代价是平均证据用量增加，附表耗时为本次本机测量。

评分对象是生成前证据块中的支持句，检索范围为每题自带的 distractor 候选。生成正确率、拒答正确率以及开放语料多跳检索需要各自的实验。

## BEIR SciFact 文档排序

使用全部 5,183 篇文献摘要和 300 道官方测试题。先在训练集派生的 60 道开发题比较原版混合、纯词法、纯向量和 RRF。预先指定的候选是纯向量和 RRF，开发集 nDCG@10 分别为 74.61% 和 75.79%，因此冻结 RRF，与原版混合共同进入测试。两组共用 OPay 网关的 `qwen3-embedding-4b` 和 SciFact 索引，预热查询向量，候选数上限为 64。RRF 的词法和向量各取 32 个候选。按文档去重后计算排序指标。[BEIR SciFact 数据与评价协议](https://github.com/beir-cellar/beir)

| 配置 | nDCG@10 | Recall@10 | 预热后 API p95 | 错误 |
| --- | ---: | ---: | ---: | ---: |
| 原版混合检索 | 69.65% | 82.77% | 326.1 ms | 0/300 |
| 独立词法与向量召回 + RRF | 73.65% | 87.91% | 49.6 ms | 0/300 |

nDCG@10 提升 4.01 个百分点，300 题中 76 题提升、176 题持平、48 题下降。配对 bootstrap 95% 区间为 +1.31 至 +6.79 个百分点，计算采用逐题独立的假设。Recall@10 提升 5.14 个百分点，检索门禁通过。这个对照同时改变了候选生成和排序，耗时来自本机的查询预热请求。
